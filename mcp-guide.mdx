The Reporters.io MCP server lets an assistant use the same reporter, outlet, article, and contact operations as the REST API. An active Professional (Pro) subscription is required for the MCP connection and every operation, including initialization and tool discovery. Creating an API key also requires active Pro access. Enter a name to create one; all six API permissions are included automatically, and keys do not expire automatically.

## Hosted MCP

Use Streamable HTTP at `https://reporters.io/api/mcp`. Configure your client to send your API key as a bearer header:

```json
{
  "mcpServers": {
    "reporters": {
      "url": "https://reporters.io/api/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_API_KEY"
      }
    }
  }
}
```

Replace `YOUR_API_KEY` in your client's protected settings. The exact configuration location depends on the MCP client.

## Connection reference

The public [reporters-mcp repository](https://github.com/ricciflow-api/reporters-mcp) contains server metadata, connection examples, and discovery checks for the hosted server. Use a client that supports remote Streamable HTTP and bearer headers.

## Tools and results

The hosted server exposes `get_account`, reporter and outlet search/profile tools, associated article tools, explicit contact-reveal tools, and `get_search_filters`. Tool input names match the REST contract: use `reporter_id` and `outlet_id`, and use the returned IDs instead of guessing them.

Read each tool's `structuredContent` for the full result envelope. For a deliberate retry, reuse the same optional `idempotency_key` input with identical parameters. Use a different value for a different intended request.

## Choose a workflow

Ask the assistant to search for a topic, inspect relevant reporter profiles, and cite returned article links before choosing contacts. For example:

> Find reporters covering climate technology. Review their profiles and recent article references, then give me a short, source-linked shortlist.

Contact details require a separate reveal operation. Every API key includes the contact permission automatically. The server does not send pitches or messages.

## Troubleshoot

A `401` usually indicates an API-key problem. A `403` indicates that the account does not have active Professional (Pro) access. Revoked keys do not authorize requests, and existing keys stop working after the account loses Pro access. You can still revoke existing keys in API-key management after a downgrade. The documentation and public OpenAPI specification remain readable without a subscription. Verify the same key with the REST API and read [error handling](/errors).
