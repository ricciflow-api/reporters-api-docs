The Reporters.io MCP server lets an assistant use the same reporter, outlet, article, and contact operations as the REST API. An active Professional (Pro) subscription is required for the MCP connection and every operation, including initialization and tool discovery. Creating an API key also requires active Pro access. Enter a name to create one; all six API permissions are included automatically, and keys do not expire automatically.

## Hosted MCP

Use Streamable HTTP at `https://reporters.io/api/mcp`. The [MCP dashboard](https://reporters.io/developers/mcp) also provides client setup. Set `REPORTERS_API_KEY` in the environment that launches your client, then add its configuration:

<Tabs>
  <Tab title="Claude Code">
    Merge this entry into your project's `.mcp.json`, approve the server, and check the connection with `/mcp`.

    ```json
    {
      "mcpServers": {
        "reporters": {
          "type": "http",
          "url": "https://reporters.io/api/mcp",
          "headers": { "Authorization": "Bearer ${REPORTERS_API_KEY}" }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Cursor">
    Merge this entry into `.cursor/mcp.json` and enable the server in your MCP settings.

    ```json
    {
      "mcpServers": {
        "reporters": {
          "url": "https://reporters.io/api/mcp",
          "headers": { "Authorization": "Bearer ${env:REPORTERS_API_KEY}" }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Codex">
    Add this entry to `~/.codex/config.toml` and restart the client.

    ```toml
    [mcp_servers.reporters]
    url = "https://reporters.io/api/mcp"
    bearer_token_env_var = "REPORTERS_API_KEY"
    ```
  </Tab>
</Tabs>

These clients resolve the environment variable before connecting. Do not replace it with a key in a shared file. The hosted server uses API keys, without an OAuth sign-in flow. See the [Claude Code](https://code.claude.com/docs/en/mcp), [Cursor](https://cursor.com/docs/mcp), and [Codex](https://learn.chatgpt.com/docs/extend/mcp) references for client setup details.

## Connection reference

The public [reporters-mcp repository](https://github.com/ricciflow-api/reporters-mcp) contains server metadata, client configurations, a local stdio bridge, and discovery checks for the hosted server. Use a client that supports remote Streamable HTTP and bearer headers.

## Local stdio connection

For a client that launches local MCP processes, clone the [public MCP repository](https://github.com/ricciflow-api/reporters-mcp), run `npm ci`, and configure `node /absolute/path/reporters-mcp/src/index.mjs` as the server command. Requires Node.js 20 or later. Provide `REPORTERS_API_KEY` through the client's protected environment settings.

The bridge forwards current hosted tool schemas and results. It verifies hosted access before startup, and the hosted service enforces active Pro access and key revocation on discovery and tool calls. The bridge does not cache contacts or retry calls automatically. It is not published as an npm package.

## Tools and results

The hosted server exposes `get_account`, reporter and outlet search/profile tools, associated article tools, explicit contact-reveal tools, and `get_search_filters`. Tool input names match the REST contract: use `reporter_id` and `outlet_id`, and use the returned IDs instead of guessing them.

Read each tool's `structuredContent` for the full result envelope. For a deliberate retry, reuse the same optional `idempotency_key` input with identical parameters. Use a different value for a different intended request.

## Choose a workflow

Ask the assistant to search for a topic, inspect relevant reporter profiles, and cite returned article links before choosing contacts. For example:

> Find reporters covering climate technology. Review their profiles and recent article references, then give me a short, source-linked shortlist.

Contact details require a separate reveal operation. Every API key includes the contact permission automatically. The server does not send pitches or messages.

## Troubleshoot

A `401` usually indicates an API-key problem. A `403` indicates that the account does not have active Professional (Pro) access. Revoked keys do not authorize requests, and existing keys stop working after the account loses Pro access. You can still revoke existing keys in API-key management after a downgrade. The documentation and public OpenAPI specification remain readable without a subscription. Verify the same key with the REST API and read [error handling](/errors).
